## 一、背景：为什么法律工作特别适合用 AI 来提效

先说一个观察：律师和法务最累的活，往往不是写起诉状，而是**逐条审合同、人工爬法规、月底整理案件进度**。这三件事的共同特点是——重复性高、规则明确、但工作量巨大。这恰好是 AI 最能发挥的地方。

但直接用通用聊天机器人问"这份合同有什么风险"，效果通常不好。原因是它缺乏三样东西：**你（或你所在团队）的工作规则、权威的法律数据源、以及一套固定的审查流程**。

比较有效的组合是三层结构：

| 层级 | 作用 | 类比 |
|---|---|---|
| **工作台（WorkBuddy）** | 能读写本地文件、跑脚本、调工具、做自动化 | 你的办公室和双手 |
| **技能市场** | 现成的专项能力，按需加装 | 现成的办公软件 |
| **成熟开源 Skill** | 把某个领域的完整工作流固化下来 | 团队沉淀下来的办案手册 |

这三层叠起来，AI 才从一个"会聊天的助手"变成"能按流程干活、还能自己去查数据核实的助手"。

一个关键的认知转变是：**AI 在这里的价值不只是"生成文本"，而是"带着工具去核实"**。比如让它引用法条，理想状态不是它凭印象写出"《民法典》第 X 条"，而是它真的去法律数据库里检索，把现行有效的原文取回来，并附上可点击的溯源链接。这个差别，决定了输出能不能用。

## 二、值得重点关注的 Skill：claude-for-legal-ZH

### 2.1 先说清楚：为什么官方的法律插件不能直接拿来用

Anthropic 有 `claude-for-legal`，OpenAI 有 `Astra for Law`。两者都很成熟，但拿到中文法律业务里**基本不可用**，原因不同：

- **Anthropic 版**：12 个法域插件，MIT 协议开源。但内核是美国法——UCC（统一商法典）、FLSA/FMLA/ADA（劳工与残障法）、FRCP/FRE（联邦民诉与证据规则）、GDPR/CCPA、Westlaw/CourtListener 判例库。拿它审一份中国合同，法源体系是系统性错位的，不是改几句提示词能补救的。
- **OpenAI 版**：GPT-6 Astra 的法律配置，配一个覆盖 2.3 亿 URL 的美国判例法索引。它甚至不是 Skill，而是模型配置加插件生态，且目前只向美国 Am Law 200 律所通过 Trusted Access 开放。

所以中文场景需要的不是"翻译"，而是**把法源、流程、检索路由整套换掉**。这件事已经有人做了。

### 2.2 中国法本地化版本

项目：`github.com/CSlawyer1985/claude-for-legal-ZH`

| 项 | 内容 |
|---|---|
| 维护者 | 陈石律师（浙江海泰律师事务所） |
| 定位 | Anthropic 官方套件的**中国法深度本地化版** |
| 规模 | 16 个业务领域 · 174 个技能 · 12 个领域 Agent |
| 协议 | **Apache 2.0（明确可商用）** |
| 版本 | v1.1.0（2026-09-28 更新） |

它的价值全在下面这张替换表里——这不是翻译，是把法源体系整套换了：

| 美国法原版 | 中国法改造后 |
|---|---|
| UCC 统一商法典 | 民法典合同编 |
| FLSA / FMLA / ADA | 劳动合同法 / 劳动争议调解仲裁法 / 工伤保险条例 |
| FRCP / FRE | 民事诉讼法 / 民诉法司法解释 / 证据规定 |
| GDPR / CCPA | 个人信息保护法 / 数据安全法 / 网络安全法 |
| Westlaw / CourtListener | 元典 / 人民法院案例库 / 北大法宝 |

另有 10 个领域内置了自足的中国法核心规则参考文件（民法典合同编、2024 新公司法、个保法核心条款、民诉法核心等），所有引用法条带 `[法条原文]` 溯源标签——**不联网也能跑**。

### 2.3 它原生支持 WorkBuddy

这点很关键。它不绑定单一运行环境，同时适配 Claude Code、Codex、DeepSeek Harness 和 WorkBuddy 四端。对 WorkBuddy 有专门的适配层：

- 共 **21 个技能**：16 个业务领域 + 5 个托管工作流
- 业务领域包括：商事合同、公司并购、劳动用工、隐私数据、产品合规、监管合规、AI 治理、知识产权、争议解决、刑事（强制脱敏）、政府采购、中国法研究、律师客户服务等
- 5 个托管工作流：尽调网格、期限盯盘、上线风控、法规监控、续约预警

用法上不用记任何命令，直接说人话就行。比如"请审查这份供应商合同，重点看责任限制、解除、赔偿、数据处理和争议解决"，技能会自动匹配触发。

### 2.4 它自带的安全设计（这点值得肯定）

- 所有输出定位为**律师审查草稿**，明确不替代律师判断
- 每条引用标注来源；管辖权假设**明示标注**
- 仅来自模型知识、未经检索核实的引用，会被标记为 `[需验证]`
- 涉主观法律判断默认保守处理；提交、发送前设有明确门槛

用一句话概括它的定位：**不是套律师人设的提示词，是把中国法律体系、检索路由和审查流程整套装进了 Skill。**

## 三、WorkBuddy 平台自带的法务能力

除了外部 Skill，WorkBuddy 本身也提供了几类法务相关的现成能力，装机即可用。

### 3.1 连接器：把法律数据库接进来

这是最重要的一类——它决定 AI 能不能"查到真东西"。

| 连接器 | 能力 |
|---|---|
| **华宇元典** | 法规、法条、司法解释检索；1.83 亿+ 裁判文书；企业涉诉/失信/被执行/股权冻结；上市公司公告与证券监管案例 |
| **北大法宝** | 语义与关键词双模式检索法规、法条、案例；**可把文本中的法条引用与案号回库逐条比对、对齐标准名称、输出可溯源链接** |
| **企查查·法律数据** | 全量现行法律/行政法规/司法解释，法规级到法条级逐字正文，2.5 万+ 权威案例 |
| **法研** | 现行有效的法规条文检索 |
| **威科先行** | 法规与案例的语义、关键词检索 |
| **企查查 / 天眼查 / 启信慧眼** | 工商登记、股东结构、实际控制人、受益所有人、对外投资——签约前主体核验用 |

其中"引用回库比对"这类能力值得单独说一句：它的价值不是多一个数据库，而是给你的输出加了一道**幻觉校验门禁**。在成果正式交付之前跑一遍，能把编造的法条和失效的引用挑出来。

### 3.2 技能市场的现成法律技能

| 技能 | 特点 |
|---|---|
| **AI律师网合同审查** | 6 合 1：批量审查（PDF/DOCX/TXT/图片）、数据合规（PIPL/DSL/CSL）、Word 原生修订痕迹逐句修订、25+ 合同类型与风险分级、民法典合同编司法解释全量映射 |
| **法宝律爱多合同审查** | 输出风险、修订建议、上报事项与审查报告 |
| **合同智能审查** | 13 大类风险初筛 + 可视化 HTML 报告，便于衔接内部审批 |
| **法律法规检索** | 查法条、查司法解释、核验法规时效性的专用入口 |

### 3.3 专家与资料库

- **专家**：可加载"合同审查法律专家"，支持完整离线分析，适合涉密材料。
- **资料库**：可沉淀历史审查意见、合同范本库、团队通用的审查手册。注意它是云端空间，**建议只放脱敏后的模板与方法论，不放未经脱敏的合同原文**。

## 四、开源社区：先分清"能用的工具"和"工具目录"

### 4.1 两类东西不要搞混

到开源社区找法律 AI 工具，第一件事是分清你看到的属于哪一种：

| | **可直接用的技能套件** | **索引目录（awesome list）** |
|---|---|---|
| 典型例子 | `claude-for-legal-ZH` | `awesome-legal-ai-zh` |
| 里面装的是什么 | 可执行的 `SKILL.md` 与配套代码 | 一串仓库地址和评价 |
| **装完会怎样** | 技能面板多出若干技能，说人话就能触发 | **什么也不会发生** |
| 类比 | 一整套办案手册 | 工具选购目录 |

判断方法很简单：**看仓库里有没有 `SKILL.md`**。有，才可能装进你的工作台；没有，那它就只是一份文档。

这一点尤其要提醒新手：别看到"收录 200+ 个项目"就以为装完能多出 200 个技能。**它给的是地址，不是东西**——看中哪个，还得单独再去装。

### 4.2 awesome-legal-ai-zh：把它当成你的采购手册

`jetwu/awesome-legal-ai-zh` 本身不干活，但它是目前中文法律 AI 领域最扎实的一份索引，值得收藏：

- **200+ 个经核验的开源仓库**，按工作场景分类
- **明确标注能否商用**——只要你的产出是用于工作而非个人学习，这一栏就是必看的
- **标注核验深度**（元数据核验 / 仓库审阅 / Smoke 通过 / 测试通过）
- 不以 Star 数排序，而按实际任务场景给出"当前推荐"与"关键备选"

### 4.3 什么时候该去翻它

前面介绍的中国法技能套件是**日常主干**，横向覆盖了合同、劳动、知产、诉讼、合规等主要领域，日常大部分活儿它都能接。

**主干覆盖不到的时候，再去翻这份索引。** 典型的场景比如：

- 需要把审查意见做成 Word 修订痕迹的正式交付件
- 有一堆案件材料的扫描件要解析归档
- 要算诉讼期限、排期管理
- 涉外业务要查域外法、做制裁名单筛查
- 材料交付前需要脱敏

这类任务往往单点很深，通用套件做不细，翻索引找专门工具更划算。

几个典型场景的查找方向：

| 场景 | 值得关注的项目 |
|---|---|
| 合同审查并交付 Word 修订 | `cat-xierluo/contract-copilot.skill`（有 DOCX 回归测试） |
| 法律文书 Word 排版 | `lilialla/legal-document-format-skill`（67 项测试通过） |
| 案件材料扫描件解析 | `opendatalab/MinerU`（PDF/OCR 生态成熟） |
| 诉讼期限管理 | `SimbaCD/legal-period-manager-skills` |
| 域外法研究（涉外） | `imchongliu/foreign-law-research` |
| 制裁名单筛查（涉外） | `opensanctions/opensanctions`（337 个名单源） |
| 本地材料脱敏 | `moyupeng0422/legal-doc-redactor`（离线，不出本机） |

### 4.4 翻到项目后，先做两件事再装

**第一件：看许可证。** 只要这份东西是要用在**工作产出**上，而不是自己学着玩，这一条就没有商量余地：

| 许可证 | 能不能用于工作产出 |
|---|---|
| MIT / Apache 2.0 | ✅ 可以，通常需保留署名 |
| **CC BY-NC** | ❌ **禁止商业性使用**，仅限个人学习研究 |
| **CC BY-NC-ND** | ❌ 禁止商业性使用，且禁止修改后分发 |
| 无任何许可证声明 | ⚠️ **不等于可自由使用**，需联系作者确认 |

几个具体的红线：

- `Youchu-lawhub/*` 系列：CC BY-NC-ND 4.0，且附加禁止 AI 训练、禁止企业/政府使用
- `Emnllawlab/legal-translation-workflow`：CC BY-NC，不可用于收费生产
- `zj-ai-lab/shuanglv-legal-skills`：限制公开修改版分发及 SaaS / 收费 Agent 集成

**第二件：看它支不支持你的工作台。** 一个活例子很能说明问题：

`cat-xierluo/legal-skills`（杨卫薪律师维护，724 star，更新活跃）在这份索引里被列为**"当前推荐"**。它确实优秀——66 个技能加 9 个专家套件，覆盖诉讼分析、合同审查、专利商标、案件管理等，还配了 OCR、语音转写、PDF 处理等一整套内容工具。

但对多数读者未必合适，有两个硬约束：

1. **核心法律技能是 CC BY-NC，禁止商业性使用。** 它的许可证是双轨制：内容处理类工具多为 MIT 可商用，但 `litigation-analysis`、`contract-copilot`、`patent-analysis`、`legal-proposal-generator` 这些**核心法律技能恰恰是 CC BY-NC**——要用于商业性用途，需要另外联系作者取得授权。
2. **已不再支持 WorkBuddy。** 该项目 2026-09-28 起下架了 WorkBuddy 相关技能，官方说明的原因是客户端自 v5.6.2 起对本地登录态启用加密保护。它当前明确保障的是 Claude Code、Codex、OpenClaw。

**所以"索引里的当前推荐"不等于"适合自己的场景"。** 星级、活跃度、推荐位都只是参考，许可证和平台兼容性才是硬门槛。

另外要留意数据流向：某些工具处理扫描件时会上传到云端 OCR，涉及敏感材料时不能当作"本地私有"来用。

## 五、新手上手：从零到跑通的五个步骤

### 步骤 1：先把法律数据连接器接上

这是第一步，也是最容易跳过的一步。**没有数据源，AI 引用法条就是凭印象编。**

操作：进入连接器的管理面板，找到法律类连接器（如华宇元典），完成授权。多数走 OAuth 一键授权，不需要手动填密钥。

授权后**必须重启会话**——MCP 工具列表是在会话启动时发现的，不重启的话工具不会出现，你会以为装成功了但实际调不动。

### 步骤 2：验证它是不是真的能用

别信"已连接"这三个字。重启后立刻做一次实际调用，用**不含任何敏感信息**的公开法条试，例如查《民法典》第 1062 条。

一次成功的调用应该返回这样的结果：法条原文、**时效性标注（现行有效）**、生效日期、效力级别，以及一条可点击的溯源链接。

```
中华人民共和国民法典第一千零六十二条
夫妻在婚姻关系存续期间所得的下列财产，为夫妻的共同财产……
（一）工资、奖金、劳务报酬；（二）生产、经营、投资的收益……

时效性：现行有效 | 生效日期：2021-01-01 | 效力级别：法律
```

调不出结果就先排障，别往下走。还要注意：这类法律数据库通常**按积分计费**，连接成功但账号没余额时会返回 402，那是另一种"空转"。

### 步骤 3：让 WorkBuddy 帮你安装中国法 Skill

这一步**不需要你自己敲命令**。你只要准备好一个文件夹，剩下的交给它就行。

#### 第 1 小步：建一个长期保留的文件夹

在你习惯的位置新建一个专用目录，例如 `D:\法务AI工作台`。

**这个文件夹要长期保留**——技能文件就装在这里，删掉或移动之后技能会失效。

#### 第 2 小步：把这个文件夹交给 WorkBuddy

在 WorkBuddy 中把这个目录作为工作区打开（新建会话时选择它，或切换到该目录）。这一步等于授权它在这个范围内读写文件。

#### 第 3 小步：用一句话让它去装

把下面这段话直接发给它即可：

> 请帮我把中国法技能套件装到当前工作区：
> 1. 克隆 `https://github.com/CSlawyer1985/claude-for-legal-ZH.git` 到当前目录
> 2. 运行安装脚本，**务必使用 copy 模式**：`scripts/install-workbuddy.sh copy`
> 3. 装完后检查 `~/.workbuddy/skills/` 下的 `chinese-legal-*` 目录，确认每一个里面都有 `SKILL.md`

它会自动完成克隆、安装和自查，你只需要看它最后的结果汇报。

#### 为什么要强调 copy 模式

**Windows 用户尤其要注意**：安装脚本默认的符号链接模式，在没有管理员权限时会失败——而且失败得很隐蔽：脚本照样打印"已链接"，但生成的目录其实是**空的**。只有用 copy 模式才一定成功。

代价是仓库更新后需要重跑一次安装（不能靠自动更新）；好处是确定能用。

#### 装完之后

重启会话，然后在技能面板里确认出现了 `chinese-legal-` 开头的技能。

如果发现技能能出现但干活时找不到内容，多半是仓库路径登记成了 Git Bash 专用格式（形如 `/d/xxx`）。让 WorkBuddy 把 `~/.workbuddy/legal-zh/repo` 这个文件改成 Windows 通用格式（形如 `D:/xxx`）即可。

#### 如果你想自己动手

命令行方式是这样的：

```bash
git clone https://github.com/CSlawyer1985/claude-for-legal-ZH.git
cd claude-for-legal-ZH
scripts/install-workbuddy.sh copy
```

装完请抽查几个目录，确认里面有 `SKILL.md`，**不要只信安装输出**。

### 步骤 4：做一次冷启动配置

多数法律 Skill 支持"冷启动面试"：它会问你所在的机构类型、常用模板、不可让步的条款、审批路径、管辖范围，然后把答案存成你的**工作画像**并写入配置文件。

**这一步别跳过。** 不做配置，输出就是泛泛而谈的通用意见；做完之后，它才知道"责任上限必须是 2 倍服务费"这类你的具体规则。

### 步骤 5：建立复核习惯，把它当草稿用

最后这一步是工作习惯，不是技术操作：

- AI 输出定位为**审查草稿**，不是法律意见
- 法规、案例、期限、监管动态这些**时效性内容，依赖前必须回可靠来源核验**
- 交付前跑一遍引用核验，把失效和疑似虚构的引用挑出来
- 涉密材料优先用支持离线分析的专家或本地工具

## 小结

一套可用的法务 AI 工作台，本质是三件事的组合：

1. **一个能调工具的工作台**（WorkBuddy）——负责读写文件、跑流程、连数据
2. **一个权威的法律数据源**（元典 / 北大法宝等）——负责让引用真实可溯源，治幻觉
3. **一套固化的中国法工作流**（claude-for-legal-ZH 等）——负责把审查流程标准化

三者缺一不可。只有前两者，AI 不知道按什么流程干活；只有后两者，它没法落地到你的文档和工作材料里。

最后提醒一句：这套东西的价值是**把重复劳动的时间还给你**，不是替代你的判断。省下来的时间花在判断和风险权衡上，才是它真正的意义。
